# 架构说明：Django 服务端渲染（SSR）

> 本文说明本系统的技术形态与请求链路，用于设计文档 / 答辩说明 / 论文"系统设计"章节引用。
> 结论先行：系统采用 **Django 服务端渲染（Server-Side Rendering）**——浏览器发起 URL 请求，服务端视图函数（或类视图）查库、拼装上下文，模板引擎渲染出完整 HTML 返回。**没有前端框架（Vue/React），没有打包构建步骤，也没有前端通过接口二次取数。**

---

## 一、整体链路

```
① 浏览器 GET /accounts/members/?keyword=林&page=2
        │  （只有 URL 和查询串，不携带任何前端路由状态）
        ▼
② URLconf  config/urls.py → accounts/urls.py → MemberListView
        │
        ▼
③ 视图层  accounts/views.py: MemberListView(PermRequiredMixin, ListView)
        │   ├─ 权限校验：permission_required = "accounts.view_member"
        │   ├─ get_queryset()：ORM 查询 + 关键字/等级/状态过滤 + annotate 计数
        │   └─ get_context_data()：paginate() 分页 → context 字典
        ▼
④ 模板层  templates/accounts/member_list.html
        │   {% extends "base.html" %} + {% for m in members %} + {{ m.name }}
        │   （base.html 中的侧栏菜单由 context_processors.navigation 按权限注入）
        ▼
⑤ 响应   HTTP 200 + 完整 HTML（表格、分页条、按钮均由服务端拼好）
        ▼
⑥ 浏览器只负责排版与少量交互（折叠、确认弹窗、图表容器）
```

一次请求 = 一次完整的"查库 → 渲染 → 返回"，页面内容在服务端就已经是最终形态，查看网页源代码即可看到表格数据。

## 二、分层职责

| 层次 | 位置 | 职责 | 关键技术点 |
|---|---|---|---|
| 路由层 | `config/urls.py`、各 app `urls.py` | URL → 视图映射，`app_name` 命名空间 | `{% url %}` 反向解析，避免硬编码路径 |
| 视图层 | `accounts/views.py` 等 6 个文件，共 45 个视图（39 CBV + 6 函数视图） | 取参、查库、组装上下文、处理表单、跳转 | CBV（ListView/CreateView/UpdateView/DetailView）+ `PermRequiredMixin` |
| 表单层 | 各 app `forms.py` | 字段校验、错误信息中文化 | `ModelForm` + `clean_xxx` 自定义校验 |
| 模型层 | 各 app `models.py` | 数据结构、业务规则、状态机 | ORM、`STATUS_FLOW` 状态机、`clean()` 约束 |
| 模板层 | `templates/` 32 个 HTML | 结构与展示，继承 `base.html` | 模板继承、`{% include %}`、自定义过滤器 `ui_tags` |
| 公共层 | `core/` | 菜单、操作日志、权限 mixin、分页/编号工具、上下文处理器 | `Menu` 表 + `Permission` 双维度、`record_log()` 留痕 |

## 四、代码走查：一次列表渲染

**视图**（`accounts/views.py:147`）：

```python
class MemberListView(PermRequiredMixin, ListView):
    model = Member
    template_name = "accounts/member_list.html"
    permission_required = "accounts.view_member"
    context_object_name = "members"

    def get_queryset(self):
        qs = Member.objects.select_related("user").annotate(
            order_count=Count("orders", distinct=True),
            appointment_count=Count("appointments", distinct=True),
        )
        keyword = self.request.GET.get("keyword", "").strip()
        if keyword:
            qs = qs.filter(Q(name__icontains=keyword) | Q(phone__icontains=keyword)
                           | Q(member_no__icontains=keyword) | Q(tags__icontains=keyword))
        return qs.order_by("-created_at")

    def get_context_data(self, **kwargs):
        ctx = super().get_context_data(**kwargs)
        ctx["page_obj"] = paginate(self.request, self.get_queryset(), 10)
        ctx["members"] = ctx["page_obj"]
        ctx["levels"] = Member.LEVEL_CHOICES
        return ctx
```

**模板**（`templates/accounts/member_list.html`）：

```django
{% extends "base.html" %}
{% block content %}
  <form method="get" class="filter-bar">   {# 筛选直接提交 GET，服务端重新查询 #}
    <input name="keyword" value="{{ keyword }}">
  </form>
  <table>
    {% for m in members %}
      <tr>
        <td>{{ m.member_no }}</td>
        <td>{{ m.name }}</td>
        <td>{{ m.get_level_display }}</td>
        <td>{{ m.order_count }}</td>
      </tr>
    {% endfor %}
  </table>
  {% include "core/_pager.html" %}        {# 分页条由服务端渲染出页码链接 #}
{% endblock %}
```

筛选、排序、翻页全部表现为 **URL 查询串变化 + 服务端重新渲染**，不存在"前端发 AJAX 再局部替换 DOM"的过程。

## 五、写操作遵循 PRG（Post–Redirect–Get）

所有新增 / 修改 / 状态流转都是标准表单提交：

```
用户提交表单 (POST，带 csrfmiddlewaretoken)
   → 视图 form.is_valid() 校验（失败则带错误信息重新渲染同一模板）
   → form.save() 写库 / 状态机校验 + 套餐次数核销（transaction.atomic）
   → record_log() 写操作日志
   → messages.success("...")
   → HttpResponseRedirect（302）
   → 浏览器 GET 回列表页，渲染带提示条的完整 HTML
```

好处：刷新不会重复提交，提示信息通过 Django messages 框架在下一个请求的模板中渲染。

## 六、如何证明它不是"前端假数据网页"

| 检查项 | 结果 |
|---|---|
| 模板 / 静态 JS 中的 `fetch(`、`axios`、`XMLHttpRequest` | **0 处**（全站无前端取数） |
| 视图中的 `JsonResponse`（前后端分离接口特征） | **0 处** |
| 视图数量 / 渲染方式 | 45 个视图（39 个类视图 + 6 个函数视图）；类视图靠 `template_name` 渲染，函数视图用 `render()` 显式返回 |
| 模板数量 | 32 个，全部继承自 `base.html` |
| 数据来源 | 数据库（SQLite / MySQL 可切换），非 localStorage |
| 权限校验位置 | 服务端视图 mixin + 模板 `{% if perms.xxx %}`，前端改 DOM 无法越权 |
| 分页 / 筛选 | URL 查询串驱动，服务端 `Paginator` |

## 九、可直接引用的一段话

> 本系统采用 Django 服务端渲染架构。浏览器通过 URL 发起请求后，由 URLconf 路由至对应视图；视图基于 Django ORM 完成数据查询与业务计算，将结果组织为上下文（context），交由 Django 模板引擎渲染为完整 HTML 文档返回。系统未引入 Vue、React 等前端框架，也无前端构建流程：页面的筛选、排序与分页均通过 URL 查询参数驱动服务端重新查询与渲染，表单提交遵循 Post–Redirect–Get 模式，操作结果借助 messages 框架在页面中回显。菜单与按钮的可见性由服务端根据用户角色与权限动态生成，权限校验在视图层强制执行，避免了前端篡改带来的越权风险。
