# 项目说明

## 一、系统定位

中医养生馆日常业务的三个痛点：会员档案散落在纸质表格、套餐购买与核销两张皮、服务过程无法追溯。
本系统把「养生服务管理 → 套餐订单管理 → 服务预约管理 → 查询统计与日志」串成一条可追溯的业务闭环：

```
养生服务（服务项目主数据）
      │  组合成
      ▼
养生套餐 Package ── 下单 ──▶ 套餐订单 Order ── 展开 ──▶ 订单明细 OrderItem（购买次数 / 已用次数）
                                                              │  核销
                                                              ▼
                                              服务预约 Appointment（审核 → 服务 → 完成）
                                                              │
                                                              ▼
                                        异常备注 / 附件 / 处理历史 / 订单与预约状态留痕
                                                              │
                                                              ▼
                                     多条件查询 · 统计报表 · 操作日志 · 导出与打印
```

设计要点：

- **信息留痕**：订单状态流转（`OrderStatusHistory`）、预约全流程（`AppointmentHistory`）、服务价格变更（`ServicePriceHistory`）、操作日志（`OperationLog`）四层留痕，任何一条业务数据的来龙去脉都可查。
- **流程规范**：订单与预约都用显式状态机（`STATUS_FLOW`）约束流转，非法跳转被前后端双重拦截。
- **权限可控**：用户 → 角色（Group）→ 菜单（Menu）+ 接口权限（Permission），页面入口与后端视图都做校验。
- **数据一致**：预约完成自动核销明细次数，订单金额随明细变动自动重算，删除被引用的服务被 `PROTECT` 拦住。

## 二、技术实现

| 层次 | 选型 | 说明 |
| --- | --- | --- |
| Web 框架 | Django 5.2（MTV） | 类视图 + Mixin 复用权限与分页逻辑 |
| 数据库 | SQLite（默认）/ MySQL 8 | `DB_ENGINE=mysql` 环境变量切换，`PyMySQL` 驱动 |
| 模板 | Django Template + Bootstrap 5 | 静态资源本地化，断网可用 |
| 交互 | 原生 JavaScript | 套餐联动、金额试算、图表渲染、打印 |
| 统计 | Pandas + ECharts | Pandas 做清洗汇总，ECharts 出图 |
| 导出 | csv（UTF-8 BOM） | Excel 直接双击打开不乱码 |

## 三、5 名学生功能分工

### 学生 1：用户与会员管理（`accounts`）

| 子功能 | 入口 | 视图 | 说明 |
| --- | --- | --- | --- |
| ① 用户注册 / 登录 / 退出 | `/accounts/register/`、`/accounts/login/`、`/accounts/logout/` | `RegisterView`、`UserLoginView`、`UserLogoutView` | 注册即建账号 + 会员档案并自动登录；登录按角色跳转，登录成功/失败均记日志 |
| ② 会员注册、等级与资料维护 | `/accounts/members/`、`/create/`、`/<pk>/`、`/<pk>/edit/`、`/profile/` | `MemberListView`、`MemberCreateView`、`MemberDetailView`、`MemberUpdateView`、`ProfileView` | 会员编号自动生成（HY+年月+序号）；等级（普通/银卡/金卡/钻石）联动折扣与积分；会员本人只能改基础资料 |
| ③ 角色、菜单与接口权限配置 | `/accounts/roles/`、`/accounts/roles/<pk>/permissions/`、`/accounts/users/`、`/accounts/users/<pk>/role/` | `RoleListView`、`RolePermissionView`、`UserListView`、`UserRoleUpdateView` | 权限矩阵按「业务对象 × 操作」呈现；勾选菜单会自动补齐对应接口权限；无权访问返回 403 页面 |

### 学生 2：养生服务管理（`services`）

| 子功能 | 入口 | 视图 | 说明 |
| --- | --- | --- | --- |
| ① 服务信息新增 | `/services/create/` | `ServiceCreateView` | 编码唯一且自动大写；标准价 > 0、会员价不高于标准价、时长 10–480 分钟的校验 |
| ② 编辑 / 删除 / 详情 | `/services/<pk>/edit/`、`/<pk>/delete/`、`/<pk>/` | `ServiceUpdateView`、`ServiceDeleteView`、`ServiceDetailView` | 改价自动写入价格变更历史；被套餐 / 订单 / 预约引用时禁止物理删除，提示改为下架；详情页展示套餐引用、预约记录、价格变更 |
| ③ 列表分页与条件筛选 | `/services/` | `ServiceListView` | 关键字（名称/编码/简介/适宜人群）+ 分类 + 状态 + 价格区间 + 排序；分页每页 8 条，可调 `per_page` |

### 学生 3：套餐订单管理（`orders`）

| 子功能 | 入口 | 视图 | 说明 |

### 学生 4：服务预约管理（`appointments`）

| 子功能 | 入口 | 视图 | 说明 |

## 五、验收演示路径（一条业务闭环）

1. `admin` 登录 → 工作台查看概览与近 7 日预约趋势。
2. 「养生服务」新增一条服务 → 列表用关键字检索 → 进入详情。
3. 「套餐订单」为该会员下单 → 订单详情查看自动展开的明细与金额 → 追加/修改一条明细观察金额重算 → 「确认收款」流转状态。
4. 「服务预约」新增预约并关联该订单明细 → 「审核确认」→「开始服务」→「完成服务」（明细已用次数 +1）。
5. 在预约详情填写异常备注、上传附件，查看处理历史时间轴。
6. 「多条件查询」按会员+时间检索订单与预约 → 「导出」CSV → 「打印」另存 PDF。
7. 「统计报表」查看 KPI、趋势与排行 → 「操作日志」核对上述每一步是否留痕。
8. 换 `therapist`、`member01` 登录，验证菜单与按钮随权限变化，直接输入无权 URL 返回 403。

## 六、可扩展方向

- 预约排班与产能模型（顾问每日可服务次数上限、自动推荐时段）。
- 套餐到期提醒与短信/邮件通知。
- 会员健康档案的结构化指标（体质测评量表、复诊对比曲线）。
- 报表缓存与异步导出（大数量级下的性能优化）。
