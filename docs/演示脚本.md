# 个人功能演示脚本（5 名学生）

## 演示前 60 秒准备

```bash
python manage.py seed_demo --reset      # 重置为干净的演示数据
python manage.py runserver 8000
```

- 浏览器打开 `http://127.0.0.1:8000/`，统一密码 `demo123456`。
- 建议开 2 个浏览器窗口：一个用员工账号操作，一个用 `member01` 看会员视角。
- 每人演示 3–4 分钟：**说一句业务背景 → 演示 3 个子功能 → 指一下留痕证据**。

---

## 学生 1：用户与会员管理

**背景一句话**：「养生馆既要管员工，也要管会员，两类人用一套登录体系，但看到的东西完全不同。」

| 步骤 | 操作 | 讲解要点 |
| --- | --- | --- |
| 1 | 打开登录页 → 点「注册会员」，填姓名/手机号/密码提交 | ① 注册一次同时创建登录账号与会员档案，会员编号自动生成（HY+年月+序号），注册后自动登录 |
| 2 | 退出 → 用 `service` 登录 → 「会员档案」列表 → 关键字「宋」检索 → 打开「宋青禾」详情 | ② 详情页把档案、订单、预约放在一屏，等级对应折扣与积分；编辑页可升级会员等级，保存后日志记录「等级 普通 → 金卡」 |
| 3 | 用 `member01` 登录 → 自动进「会员中心」 | 会员只能看到本人资料、本人订单与预约；菜单里没有员工功能 |
| 4 | 换 `admin` → 「角色权限」→ 选「健康顾问」→ 勾选/取消某个菜单 → 保存 | ③ 菜单勾选会自动补齐对应接口权限；再用 `therapist` 刷新页面，菜单随之变化 |
| 5 | 用 `member01` 直接访问 `http://127.0.0.1:8000/services/` | 返回 403「当前角色无权访问该功能」——权限是后端拦截，不只是隐藏按钮 |

**留痕证据**：「操作日志」中可看到「会员注册」「修改会员档案」「配置角色权限」三条记录。

## 学生 2：养生服务管理

**背景一句话**：「服务项目是所有业务的源头，价格、时长、禁忌一旦定错，后面订单和预约都会跟着错。」

| 步骤 | 操作 | 讲解要点 |
| --- | --- | --- |
| 1 | 用 `service` 登录 →「养生服务」→「新增服务」→ 编码 `SVC900`、名称「演示艾灸」、分类艾灸理疗、时长 60、标准价 268、会员价 238 | ① 提交前试试：会员价填 999 会被拦（不能高于标准价）；时长填 5 会被拦（10–480 分钟） |
| 2 | 保存后进入详情 →「编辑」把价格改为 288、状态改为下架 → 保存 | ② 详情页出现「价格变更记录」：258→288，操作人是自己；再次上架后列表状态标签变灰/变绿 |
| 3 | 回到列表 → 关键字「艾灸」+ 分类「艾灸理疗」+ 价格 200–300 + 按价格降序 | ③ 分页每页 8 条，URL 上带着筛选参数，翻页不丢条件 |
| 4 | 找一条已被套餐引用的服务点「删除」 | 被 `PROTECT` 拦住，提示「已被套餐/订单/预约引用，无法删除，建议下架」——数据完整性讲解点 |

**留痕证据**：服务详情页价格变更记录 + 操作日志「新增养生服务 / 编辑养生服务」。

## 学生 3：套餐订单管理

**背景一句话**：「会员买的不是单个项目，是套餐；一次下单要能拆成多条明细，还要能核销。」

| 步骤 | 操作 | 讲解要点 |
| --- | --- | --- |
| 1 | 用 `clerk` 登录 →「套餐订单」→「新建订单」→ 选会员「许静姝」（钻石卡）+ 套餐「肩颈舒缓 10 次卡」+ 数量 1 + 优惠 100 | ① 页面右侧实时试算套餐包含的服务与次数；保存后订单号 TK 开头，**明细自动展开**（推拿 6 次 + 经络 4 次），单价已按钻石卡 0.85 折计算 |
| 2 | 订单详情 →「追加明细」加一条「中药足浴 × 4」→ 观察合计金额变化 | ② 金额随明细实时重算；重复添加同服务会被拒；把「已用次数」改成大于购买次数会被拒 |
| 3 | 修改某条明细的购买次数 → 再删除一条明细 | 每次改动都重算合计，并提示至少保留一条明细 |
| 4 | 点「确认收款」→ 状态从待付款变已付款；状态时间轴出现流转记录 | ③ 状态机只允许合法流转（不能从待付款直接完成）；付款后会员积分自动增加；详情页联动显示该订单产生的预约 |

**留痕证据**：订单详情「状态时间轴」+ 会员详情页积分变化 + 操作日志「创建套餐订单 / 变更订单状态」。

## 学生 4：服务预约管理

**背景一句话**：「会员到店做服务，从约时间到做完，中间可能有迟到、改期、身体不适，全过程要能追溯。」

| 步骤 | 操作 | 讲解要点 |
| --- | --- | --- |
| 1 | 用 `therapist` 登录 →「服务预约」→「新增预约」→ 选会员 + 服务 + 关联一条订单明细 + 日期时段 | ① 联系电话自动带出；选过去的日期会被拒；同一顾问同一天同一时段重复预约会被提示冲突 |
| 2 | 打开预约详情 →「审核确认」→「开始服务」→「完成服务」 | ② 走完流程后：确认人、确认时间、完成时间落值；**关联订单明细的已用次数 +1**（套餐核销闭环） |
| 3 | 试试跳过步骤直接「完成服务」，或换一个没有审核权限的账号点「审核确认」 | 状态机与权限双重拦截：前者提示「当前状态不能执行」，后者提示「缺少审核服务预约权限」 |
| 4 | 填「异常备注」（等级选紧急 + 说明）→ 上传一个 txt/pdf 附件 → 看历史时间轴 | ③ 异常等级用颜色区分；附件限制 5MB、限 PDF/图片/Word/txt；上传、备注、每次状态变化都进历史 |

**留痕证据**：预约详情「处理记录」时间轴（创建 → 审核 → 开始 → 完成 → 更新备注 → 上传附件）。

## 学生 5：查询统计与日志

**背景一句话**：「老板不关心表结构，只关心三件事：这个月卖了多少、谁在干活、出了事能不能查。」

| 步骤 | 操作 | 讲解要点 |
| --- | --- | --- |
| 1 | 用 `reporter` 登录 →「多条件查询」→ 数据集切到「套餐订单」→ 关键字 + 状态 + 日期范围 → 查询 | ① 5 个数据集（订单/预约/会员/服务/日志）共用一套条件；结果分页，每次查询都记一条查询日志 |
| 2 | 点「导出」→ 用 Excel 打开 CSV | ③ 导出遵守当前筛选条件；UTF-8 BOM 保证中文不乱码；再点「打印」看 A4 版式（可另存 PDF） |
| 3 | 进「统计报表」→ 看 KPI、每日营收/预约趋势、预约状态分布、服务 TOP8、顾问工作量、套餐经营排行 | ② 数据由 Pandas 清洗汇总（空值填充、日期对齐、分组聚合），ECharts 出图；改日期区间图表联动刷新 |
| 4 | 进「操作日志」→ 按类别「业务操作」+ 操作人筛选 → 找到刚才演示产生的记录 | ③ 每一步业务动作都有留痕：谁、什么时候、对哪个单号、做了什么 |

**留痕证据**：日志页能按单号反查全部动作，形成「查询—导出—留痕」闭环。

---

## 统一收尾话术（任一人可讲）

> 这套系统的价值不在页面多少，而在**闭环**：服务定标准 → 套餐组合服务 → 订单展开明细并收款 → 预约核销次数 → 全程写入历史与日志 → 最后能按条件查出来、导出去、打出来。
> 技术上用 Django 的权限体系把「菜单可见」和「接口可调用」绑在一起，用状态机约束流程，用四张留痕表保证任何一条数据都可追溯。
